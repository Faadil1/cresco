## Extracted, project-specific patterns

| Playbook mechanism | CRESCO use | Proof required; cannot infer |
| --- | --- | --- |
| Define a person/job/result | Family Promise Card grounded in a parent's most recent real authorization/boundary event | Whether this recurring problem merits a product |
| Qualify an opt-in early group | Separate expert panel, parent cohort and delegated-capital cohort | Interest in an invitation is not adoption |
| Build patterns from episodes, include counterexamples | Ask about last real incident, alternative and consequences | Anecdotes do not prove prevalence or demand |
| Watch authentic tasks | Extend the existing World's Fair A/B/C test kit, track exact build/role and assistance | Completing a task once is not retention |
| Explain improvement and retest | Decision Receipt with two explanations, predeclared expected result and comparable retest | UI polish is not solved business pain |
| Prove value before widening | Value and Cohort Review, repeated need, support burden, voluntary next action | Small selected samples cannot estimate market size |

The playbook's sample recruiting counts, interview formats and metrics are **planning heuristics**, never claims of statistically supported thresholds. Any acceptance thresholds in this folder are local operational decision rules, subject to review after real learning.

- CRESCO's `state/CURRENT.yaml` records a post-slice Devnet capability and an external-value gap. This folder addresses that gap **without** displacing the primary product-exploitation work or changing any canonical current-state field until reviewed.
- The existing user-test kit already specifies usability tasks and basic targets. **Do not replace it**; add qualification, source records, consent, hypothesis alternatives, repeated use and explicit decision.
- Existing Family and Delegated Capital narratives are separate hypotheses and must not be combined into fabricated product-market fit.
- A technical pass remains a technical pass. A user interview remains a reported episode; an observed task is task evidence; return for a need is a repeat-value signal; payment or contracting is separate commercial evidence.
