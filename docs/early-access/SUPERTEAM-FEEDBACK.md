# Superteam / Solana ecosystem expert-feedback protocol

**Status:** INVITATION RECEIVED / SESSION NOT YET BOOKED OR HELD. A member of the ecosystem offered text feedback or a 30-minute call in a private Telegram conversation. Do not place original chat screenshots, private handles, contact information, or purported expert quotes in this public repo.

## Purpose and boundary

Use the offered 30 minutes to challenge Cresco's technical and product assumptions, not to manufacture customer testimonials. Expert-review outcomes should be classified as **EXPERT_REVIEW**; user interviews, first-value observations, repeat use and willingness to pay need independent records.

Coordinate the time with the teammate first; no calendar booking or message send is implied by this document. Only share the safe public home URL and verified evidence links. No secrets, private workspace/role URLs, personal wallets, unmerged version represented as live, or funds.

## 30-minute conversation (moderator can adapt)

| Time | Purpose | Concrete artifact |
| --- | --- | --- |
| 0–3 min | One-sentence CRESCO job and what currently works on Devnet | Record the hypothesis understood or misunderstood |
| 3–9 min | Show **verified public** Family and/or Delegated Capital path, with exact deployment version noted | Time to understand; moments of confusion |
| 9–17 min | Attack authorization boundary, signer ownership, mutation/replay, market failure and wallet UX | Ranked technical risks, with next proof needed |
| 17–24 min | Challenge where the product has an urgent buyer, Solana-native residual and distribution path | Concrete counterexamples and competitors |
| 24–30 min | Ask for 1–3 major obstacles, a follow-on technical introduction or a relevant qualified tester | Next step, owner and date *if agreed* |

### Five priority questions

1. What concrete job and buyer would make this mechanism valuable, and in which lane (Family, delegated capital, something else)?
2. What would make you distrust the current authority or execution path? Which technical proof is missing?
3. What advantage remains if incumbent wallets, spending-limit products or an agent-policy provider adds exact approvals?
4. Which one journey must work without founder help before we invite external users?
5. Could you recommend suitable opt-in users/technical reviewers or a relevant support program, if available?
