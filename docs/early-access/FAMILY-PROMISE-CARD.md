# CRESCO Family — Promise Card

**Status:** HYPOTHESIS / NOT CUSTOMER-VALIDATED. Do not treat the examples below as real interview findings.

| Field | Initial testable hypothesis |
| --- | --- |
| Person / buyer | Adult parent or guardian who currently gives a young person controlled spending discretion |
| Secondary user | Teen/adolescent using a family-approved simulation or allowance flow; initial sessions can use consenting adults acting in this role |
| Trigger / situation | The young person wants to make an otherwise legitimate purchase/action beyond a usual limit, or the parent wants to reduce constant approval requests |
| Real episode | **UNKNOWN**. Ask a consenting parent for the *last actual occurrence* and record sequence, date range, what happened and consequences |
| Existing alternatives | Cash allowance, prepaid/debit card, manual approval by message, ordinary bank parental controls, no independent access — **hypotheses to verify** |
| Core job | Give appropriate independence without losing clear control over exceptional decisions |
| Product promise | The delegate acts without asking on in-bounds actions; only the exact out-of-bounds action may be authorized once, without silently widening standing permission |
| Meaningful first value | Parent and delegate understand the current limits, a real task is completed without a facilitator, and an exceptional request is appropriately approved or refused |
| Major failure | Misleading investment/ownership claims, unauthorized spend, ambiguous approval, participant exposing wallet/identity details, or inability to explain unchanged limits |
| Measurable signal | Unassisted completion and correct boundary explanation, duration and help; return when another authentic need occurs, explicit opt-in to follow-up |
| What would falsify it | Parents do not encounter this job, current methods are already good enough, demo is too complex, or no voluntary reuse despite a recurring need |
| Revenue hypothesis | A credible paying customer and buyer value **remain unknown**; never treat enthusiasm, prizes or technical demos as WTP |

## Distinct product lanes, not silently blended

**Family:** prioritize validating the parent's control problem and the young person's comprehensible autonomy. The current Family app (`/start`) and live World's Fair Family mandate workspace are **different surfaces and session systems**. Observe exactly which one each participant saw; do not imply V1 #77–#79 is on the public host.

**Delegated capital / autonomous agents:** carry out a separate Promise Card with actual allocator/operator/risk-owner roles. Ask about a recent failed or overridden capital action, approvals today, exception frequency, latency, price/risk constraints and audit burden. Validate a buyer and economics independently of Family.

## First falsifiable decision

> Are parents in the initial qualified sample experiencing an important, recurring permission-boundary problem, and can they understand CRESCO's unchanged standing limit without founder coaching?

Before the first conversation, record alternatives including **do nothing / use existing financial products**. Advance from discovery to task sessions only when the parent cohort presents concrete, eligible job episodes and participant safety is approved.

**User value is not equal to a wallet connection, a demo-token transfer, a survey score, or a signed grant.**
