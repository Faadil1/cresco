# Demo

Target: about 60 seconds.

The product mechanism should be understood before the technical proof appears.

## Spoken flow

> Cresco gives young people room to make financial decisions without asking a parent every single time.
>
> Alex has a standing Key. Inside it, he can act on his own.
>
> Here, he invests five dollars. It is inside his Key, so it goes through immediately. No parent approval.
>
> Now he tries twelve dollars. That is outside his current Key, so Cresco stops the action and explains the boundary.
>
> Alex can adjust the amount, practice it, or ask for more room.
>
> His parent now has three choices: not this time, allow once, or widen the Key.
>
> Here, the parent chooses Allow once. This approves this specific twelve-dollar request without changing Alex's standing Key.
>
> Now Alex changes the amount to eleven dollars.
>
> It refuses.
>
> The parent approved twelve dollars, not anything up to twelve.
>
> Alex goes back to the exact approved twelve-dollar action.
>
> This time, it goes through.
>
> The one-time permission is now used, while the standing Key stays exactly the same.
>
> The exception moved. The boundary did not.
>
> And if Alex tries to use that permission again, it refuses.
>
> Once really means once.
>
> The interface is not the guard. The rule is enforced in the same capital path that executes the action.
>
> Solana makes financial assets programmable. Cresco makes authority over those assets programmable for humans.

## Demo truth

- $5 is the in-bounds example.
- $12 is the boundary request.
- $11 is the changed-action negative path.
- exact $12 is the one successful use.
- replay is the consumed-permission negative path.
- standing Key remains unchanged after Allow once.
- Solana and Pyth proof appear after the human mechanism is clear.

Do not claim real securities execution, brokerage, custody, or mainnet.
