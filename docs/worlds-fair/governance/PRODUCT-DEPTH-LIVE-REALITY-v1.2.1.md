# Product Depth & Live Reality v1.2.1 — Canonical Active Rule

Status: **ACTIVE**  
Applies to: CRESCO World’s Fair product / build / hackathon workflow  
Date: 2026-09-28

## Core principles

- **Vertical Slice = entry point, not Definition of Done.**
- **Technical Proof ≠ Live Product Integration.**
- Replay/static/captured evidence alone cannot satisfy a **Live Core Loop** claim.
- **One external trial ≠ adoption.**
- Organic usage excludes scripted activity used to inflate traction.
- **Depth ≠ feature count.**
- Polish cannot compensate for weak product reality.

## Preferred order

```
REAL PROBLEM
→ NATIVE MECHANISM
→ LIVE INTEGRATION
→ PRODUCT DEPTH
→ REAL USER / OPERATOR LOOP
→ REAL CONSEQUENCE
→ EVIDENCE & OBSERVABILITY
→ UX / DESIGN
→ SUBMISSION PACKAGING
```

- Live Core Loop
- Load-Bearing Integration

- clean-room / external-dependency failure
- Post-Vertical-Slice Depth Gap Review

## Post-vertical-slice question

After every vertical slice ask:

> **What separates this slice from something a real user could use tomorrow?**

Material gaps must be closed before heavy polish.

## CRESCO-specific consequence

The existing Stocklana technical proof does **not** automatically satisfy World’s Fair live-product depth.

For any selected World’s Fair wedge, CRESCO must separately prove:
- a live core loop for the selected user;
- the load-bearing Solana integration;
- a real consequence beyond UI state;
- success + negative + boundary + recovery scenarios;
- a real operator/user surface;
- evidence/receipts sufficient for an outsider or judge to verify;
- reproducible setup and dependency-failure behavior.

## Frozen/submitted protection

Frozen or submitted projects are not silently retrofitted. Reopening requires an explicit decision and new canonical state.
